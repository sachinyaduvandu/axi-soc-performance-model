# Modeling Assumptions

This project is a cycle-approximate architectural performance model.
The purpose is to study relative performance behavior and architectural
trade-offs rather than reproduce a particular commercial SoC.

## Memory

The memory subsystem uses:

- 8 banks
- 50 ns row-hit latency
- 120 ns row-miss latency
- Bank-level serialization

The DRAM model captures row locality and bank conflicts but does not
model a complete JEDEC command/timing specification.

## AXI

The interconnect represents an AXI4-style transaction interface.

The model includes transaction IDs, burst constraints, buffering,
outstanding requests and backpressure.

It is not intended to be an AXI protocol-compliance or RTL-equivalence
model.

## Traffic

CPU, DMA and DNN traffic are synthetic architectural workloads.

Accelerator throughput reported by the DSE represents aggregate modeled
DMA/DNN memory traffic throughput.

It should not be interpreted as application-level DNN performance.

## Bandwidth

The bandwidth sweep directly exercises the modeled memory subsystem.

Therefore the reported bandwidth represents modeled memory-system
throughput under the stated timing assumptions rather than the
specification of a physical DDR or LPDDR device.

## DSE

The Pareto analysis uses:

- CPU P99 latency as an objective to minimize
- Aggregate accelerator traffic throughput as an objective to maximize

Configurations are considered Pareto-optimal when no other tested
configuration is simultaneously no worse in both objectives and strictly
better in at least one.

## Reproducibility

Results are generated by the SystemC simulator and Python DSE scripts
included in this repository.

The exact numerical results depend on the configured workload,
architecture parameters and timing assumptions.
